# 状态同步

开书/设定创建与章后维护**同一域分流**：状态类变更须写回正确宿主域（及对应 `*Timeline`），勿只堆全书 `timeline`。**重要才同步**（影响后续决策/归属/主线）；装饰性旁支与路人细节不同步。章后把会影响后续决策的变化写回**正确的域**，供连贯与防出戏。读者向：因果不断、归属不乱。

## 核心原则

1. 每章（或每关键节点）结束，更新「当下事实」。
2. 只记录会影响后续决策的变化，不抄正文。
3. **分流落库**，勿把一切塞进一张全书时间线表。

## 域分流

| 变化类型 | 写入域 |
|----------|--------|
| 全书冲突/悬念/伏笔/转折/主线节点 | `timeline`（见《事件轴规划》） |
| 人物伤势、晋升、重大抉择履历 | `role` 更新 + `roleTimeline` |
| 物品易主、损毁、认主 | `item.owner` + `itemTimeline` |
| 生物驯化、战损、易主 | `creature.owner` + `creatureTimeline` |
| 地点/势力易主、战乱、政权 | `world` 更新 + `worldTimeline` |

伏笔生命周期方法论见《伏笔账本》；**落库**用 `timeline.eventType=foreshadow` + `isResolved`。

## 章后检查清单

- **人物**：伤势、位置、知情范围、关系阶段、能力解锁 → role / roleRelation / roleTimeline
- **世界/势力**：规则暴露、势力态度、地盘得失 → world / worldTimeline
- **资源**：关键道具归属 → item / itemTimeline
- **生物**：有主/无主、战损 → creature / creatureTimeline
- **伏笔/冲突/悬念**：新增/推进/回收 → timeline
- **时间**：相对日序/`timePoint` 是否推进

## 写入自检

- 有设定变更则章节 `updateManifest` 列入对应 domain；无变更可 `noSettingChanges`
- 禁止 silently 覆盖旧事实；修订须在 content/timeline 说清

## 禁忌

- 正文已改设定，各域 timeline/档案不更新。
- 把整章剧情摘要当唯一状态（过长且难检索）。
- 人物履历、物品易主全塞进全书 `timeline` 却不更新宿主域。
