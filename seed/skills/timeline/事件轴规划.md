# 事件轴规划

时间线管因果顺序与并行线，防止前后矛盾。读者向：因果不断、伏笔有去向。

## 核心原则

1. 事件有先后与因果，不是清单堆砌。
2. 并行线（多视角/多势力）须标注汇合点。
3. 与大纲节点、伏笔回收点对齐。
4. **落库写入全书 `timeline` 实体**，勿只维护平行 Markdown 表。
5. **只建关键事件**：主线/冲突/伏笔与后续写章会引用者入库；装饰性旁支时间点不必先落库。

## 可执行清单

1. 列出主线关键事件（起因 → 转折 → 高潮 → 后果）。
2. 标注时间锚点：展示用 `timeLabel` + 排序用整数 `timePoint`（越大越靠后，推荐 YYYYMMDD）。
3. 每条事件填：`title`、`content`、`eventType`。
4. `eventType` 取值：`plot`（主线）/ `conflict`（冲突）/ `suspense`（悬念）/ `foreshadow`（伏笔）/ `turning`（转折）/ `resolution`（收束）/ `other`。
5. 可解析类型（`conflict` / `suspense` / `foreshadow`）须维护 `isResolved`；回收时写 `resolveChapterNo`（若有）。
6. 并行线：各线当前进度与下一次交汇；检查人物年龄/伤势/道具归属/势力态度一致。

## 写入自检（timeline 实体）

- `timeLabel` + `timePoint` + `title` + `content` + `eventType` 齐
- 伏笔/冲突/悬念：未回收则 `isResolved=false`；回收后果写清
- 关联章可用 `relatedChapterNo`（章号），勿传章节 UUID

## 禁忌

- 无因果的事件罗列。
- 同一角色同时出现在互斥地点且无说明。
- 回收伏笔早于埋设，或关键转折无时间锚点。
- 只用自定义表格不落库。
