# 伏笔账本

伏笔必须可追踪、可回收、回收后改变局势。读者向：不被耍——伏笔有去向。

## 核心原则

1. 生命周期：埋设 → 推进 → 提示 → 回收 → 后果。
2. 每个伏笔有状态，不能只写灵感。
3. 回收必须影响关系、规则或主线，不能回收完消失。

## 落库映射（必遵）

本 skill 可挂在世界写作区作方法论，但**产品落库在全书 `timeline`**：

| 账本概念 | timeline 字段 |
|----------|----------------|
| 伏笔条目 | `eventType=foreshadow` |
| 埋设/推进内容 | `title` + `content`；`timeLabel` + `timePoint` |
| 未回收 / 已回收 | `isResolved=false/true` |
| 回收章 | `resolveChapterNo`（章号）；关联章可用 `relatedChapterNo` |

冲突/悬念同样可用 `conflict` / `suspense` + `isResolved`。规划方法见《事件轴规划》；章后分流见《状态同步》。

勿只维护平行 Markdown「F1 表」当作唯一真相。

## 可执行清单

### 写章时

- 标注：新增 / 推进 / 回收 / 延后，并同步 timeline 实体。
- 若无新增，明确「本章无新增伏笔」。
- 过期伏笔：补回收 / 延后 / 转长线 / 放弃，并更新 `isResolved` 或 content 说明。

### 埋设质量

- 自然出现，不解释。
- 推进时换角度重复，避免一眼看穿又长期无回音。

## 禁忌

- 大量埋伏笔从不回收。
- 回收只解释设定、不改变后续行动。
- 用新万能设定覆盖未回收旧伏笔。
- 账本只在聊天/Markdown，库中无 foreshadow 事件。
