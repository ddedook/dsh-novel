# 关系与配角

关系提供情绪回报，也制造冲突；配角补主角缺口，不做工具人。读者向：关系变化可读。

## 核心原则

1. 感情线要有**好感/信任门槛**与可推进阶段，不是一见钟情后静止。
2. 配角按主角缺口配置：信息、情绪、资源、冲突、镜像、背叛。
3. 重要配角有独立目标；与主角利益不完全重合。

## 写库契约（roleRelation）

- 落库为**一条有向边**：双方引用（`from`/`to` 的 id 或 name，或 `roleId`/`targetRoleId`）+ **`relationType`** + 非空 **`content`**。
- 系统按姓名解析两端；内容页在双方人物下都展示这条边。**不要**再写一条对调的反向行（「父/子」不能原样对调）。
- 写入前先确保两个人物已存在。
- `relationType` 示例：亲属 / 师徒 / 盟友 / 仇敌 / 恋人 / 上下级 / 利用 等（与冲突阶段写进 content）。
- 关系阶段变化、决裂、结盟 → 更新或新建关系边，必要时补 `roleTimeline`。

## 可执行清单

### 关系线

- 定关系类型与当前阶段、下一阶段门槛（做什么才会变）。
- 每次互动至少推进：信息、情绪、立场、秘密之一。
- 虐点后须有补偿或反转路径，避免纯虐无回报。

### 配角功能位

| 功能 | 作用 |
|------|------|
| 信息 | 带来未知线索 |
| 资源 | 开门/给钱/给权 |
| 情绪 | 触发主题与隐痛 |
| 冲突 | 制造外部压力 |
| 镜像 | 对照主角道路 |
| 背叛 | 打破信任结构 |

### 反工具化

- 给工具型配角一次「不符合剧情便利」的选择或隐藏动机。

## 修订自检（勿单独交报告）

- 关系对是否已有 `roleRelation` 边
- 下一门槛是否可写进正文
- 配角是否补了主角缺口且有独立目标

## 禁忌

- 配角只递道具、无姓名无反应。
- 感情线无门槛、无代价、无阶段变化。
- 为推进剧情强行破人设（突然无脑、突然洗白）。
- 只写「A↔B 是朋友」散文，不落库关系边。
