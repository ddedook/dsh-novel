# 结构与卷章模板

选用宏观结构，并把卷/章写成**可执行、能支撑好正文**的节点。章纲须让读者感到：本章有事、读完有变化、章末想翻。

## 核心原则

1. 结构是工具：按篇幅与题材选用，不强行套满所有节拍。
2. **一卷一条大故事线**；**一章一条说明**，禁止「1–30章」合并。
3. 写正文必须对齐对应章的 theme / conflict / majorEvents / content。
4. 每一章说明须能支撑章节读者验收中的「净变化 + 翻页欲」。

## 结构速查

| 结构 | 适用 | 要点 |
|------|------|------|
| 三幕 | 短篇/中篇 | 25% 建置 → 50% 对抗 → 25% 结局 |
| 起承转合 | 古风/单元 | 起钩、承压、转爆、合钩 |
| 英雄之旅 | 冒险奇幻 | 召唤→门槛→试炼→归来（可裁剪） |
| 悬疑调查 | 推理惊悚 | 谜题→深入→假解答→真相反转 |

长篇：用阶段目标叠在结构上，每卷自带小三幕。

## 卷节点（写入现有字段）

身份必填：`ordinal`（卷号）+ `name`（短名，如 `骑士`）。界面显示「第1卷 骑士」，**不要**把「第1卷」写进 `name`。无父节点即为卷；也可显式 `kind=volume`。

`theme` / `conflict` / `majorEvents` 写入顶层或 **extra**（会升到顶层）；`content` 可选（本卷走向 + 卷末下一问）。

写入工具：`mutate_entities`（domain=`outline`）。**禁止** `volumeNo` / `chapterNo`。
更新已有章节点用同一 `id` 或 `ordinal` + `parentId` 定位；**禁止**同一 id 写多个章号。

质量要求（读者可读）：

- **extra.theme / extra.conflict**：本卷在追什么故事问题、主要阻力是谁/什么。
- **extra.majorEvents**：本卷关键爆发/兑现点（有序）。
- **content**（顶层）：本卷走向 + **卷末打开的下一问题**（给下卷/后续章的期待）。

## 章节点合同（写入现有字段）

身份必填：`ordinal`（章号）+ `name`（短名）+ `parentName` 或 `parentId`（所属卷）。界面显示「第1章 ××」，**不要**把「第1章」写进 `name`。有父节点即为章；也可显式 `kind=chapter_segment`。

`theme` / `conflict` / `majorEvents` 写入顶层或 **extra**；`content` 可选（走向 + 章末期待）。

| 字段 | 质量条 |
|------|--------|
| `extra.conflict` | 阻力来自谁/什么，禁止空话 |
| `extra.majorEvents` | **有序、可执行、因果相连**的必须事件；禁止「了解设定 / 日常过渡」充数 |
| `content` | 走向 + **章末期待**（翻页欲合同，供章节写作对齐） |
| `extra.theme` | 本章主题，与冲突/事件一致 |

章与章：`majorEvents` 应能看出因果（上章后果 → 本章前提），禁止可任意调换顺序的平行清单。

## 写入自检（勿单独交规划稿）

对照大纲读者五问第 4 条：随便看本章说明，能否想象写成有冲突、有净变化、有章末期待的正文？

卷/章写入时内心核对：

- 卷：追什么问题、卷内兑现点、卷末下一问
- 章：conflict 具体、majorEvents 可写且有因果、content 含章末期待

## 禁忌

- 用范围节点覆盖多章。
- 只有摘要无冲突与重大事件。
- 结构节拍与题材情绪脱节（如甜宠硬套苦难英雄之旅全程）。
- 章纲无法支撑正文净变化与翻页欲仍宣称可写。
- **大纲步只写 `domain=outline`**：禁止顺带 mutate 人物、生物、物品、世界、时间线、章节等其他域；缺设定留到对应工作区步骤。
