# 能力与代价

力量/等级体系必须可追踪：获取、限制、代价、反制。读者向：变强有门槛与代价，非数字刷屏。

## 核心原则

1. 一句话写清「最有趣的能力用法」。
2. 金手指不能替主角跳过关键成长与选择。
3. 敌人须有可见反制或误判空间。

## 写库契约（level）

落库结构：

- `system.name`：体系名称（人物境界、物品品阶等靠名称区分，可多体系并存）
- `system.category` / `system.description`：可选说明
- `system.levels[]`：有序等级；每级含 `name`，以及 `promotionCondition`（门槛）、`abilities`（能力增量）、可选 `subLevels`、`lifespan` 等

**注意**：传入完整 `levels` 会**替换**该体系旧阶梯，勿只改一级却丢其余级。

## 可执行清单

1. **核心能力**：能解决什么问题，不能解决什么。
2. **获取**：天赋/系统/传承/训练/资源/契约/代价。
3. **限制**：触发、消耗、冷却、暴露风险、使用场合。
4. **代价**：身体、资源、关系、道德、时间、污染等。
5. **反制**：同类克制、信息差、环境、规则漏洞。
6. **成长路径**：升级后解决什么新问题，引出什么新压力。
7. 每级写清「门槛 / 能力增量 / 典型冲突」→ 映射到 `promotionCondition` / `abilities`。

## 写入自检

- 体系名清晰；多体系不混名
- 每级有门槛与能力差，非空名列表
- 防崩坏约束可写在 description 或 specialRequirements（概述）

## 禁忌

- 无限制、无冷却、无暴露风险的全能金手指。
- 只写「突破了」无原因、代价、后续影响。
- 等级名堆砌而无玩法差异。
- 更新时用残缺 levels 覆盖导致阶梯丢失。
